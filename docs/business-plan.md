# のむペイのビジネス展開案

[READMEへ戻る](../README.md)

## 事業の中心：実課金による飲み忘れ防止

のむペイは、**猶予時間内に服用を記録しなかった場合に実際に課金することで、服薬に金銭的な強制力を持たせるサービス**として展開します。「飲まなければ」と思いながら後回しにしてしまう人に、期限内に行動する具体的な動機を提供し、飲み忘れを防ぐことが主な価値です。

本番では登録した支払手段で実際に課金します。現在のリポジトリは、その体験を端末内の疑似決済で再現するデモです。本資料の実決済、サーバー判定、商品販売は今後の展開計画です。

## 課金が行動につながる体験

1. 利用者が服用予定、猶予時間、課金額を設定し、課金条件に同意します。
2. 服用時刻の通知を受け、薬箱へ向かいます。
3. 服用後にQR／NFCで記録します。期限内の記録があれば、その予定に対するペナルティ課金は発生しません。
4. 猶予時間を過ぎても記録がない場合、実際に課金し、結果を知らせます。
5. 履歴を振り返り、次の服用を期限内に行う動機につなげます。

通知、QR／NFC、薬箱、履歴は、この課金による行動の後押しを支える機能です。利用者が自ら選んだ条件に金銭的な結果が伴うことを、プロダクトの中心に据えます。

システムが判定するのは服用記録の有無です。現在のQR／NFCでは実際に薬を飲んだことを自動検知できないため、記録だけで課金を回避する行動が起きないかも検証します。飲み忘れ防止の効果は今後の検証対象です。

## 想定する顧客

中心となる利用者は、毎日服薬する必要があり、通知を見ても「あとで」と後回しにしてしまう人です。自分で課金条件を選び、その条件を服薬の動機として使いたい人を想定します。

利用者への聞き取りでは、忘れる場面、通知だけでは行動できない理由、課金が行動につながるか、継続して利用できる負担かを確認します。

## 実課金サービスとして整備する仕組み

| 項目 | 本番化で整備する内容 |
| --- | --- |
| 条件の登録 | 予定・猶予時間・金額・同意内容と、その適用開始時点を保存 |
| 支払手段 | 決済サービスと連携し、支払手段の登録と課金結果を管理 |
| 期限判定 | アプリ終了中もサーバー側で予定と記録を照合 |
| 課金処理 | 同じ予定への二重課金を防ぎ、決済結果を確認して履歴へ反映 |
| 記録の同期 | 通信遅延やオフライン時の記録をどう扱うか定義 |
| 条件の変更 | 服用中止、予定変更、休止の適用時点と未確定の課金の扱いを定義 |
| 問い合わせ | 誤判定、読み取り障害、決済失敗、取消・返金への対応を整備 |

期限内に記録したのに通信が遅れた場合や、読み取りに失敗した場合の扱いは、課金への信頼を左右します。利用者に示す課金条件と実装の判定を一致させることを、本番化の要件とします。

決済事業者・利用料・具体的な課金額は未確定です。導入条件を確認しながら仕様を具体化します。

## 薬箱・ポーチ：課金システムを暮らしにつなぐ接点

![NFCスマート薬箱のやさしい暮らし](../assets/images/nfc-smart-medicine-box.png)

薬箱・ポーチは、期限内の服薬と記録を実行しやすくする商品として展開します。自宅では目に入る位置に置いた薬箱へ向かい、外出先では持ち歩き用ポーチで記録することで、同じ課金ルールのもとで服薬習慣を続ける体験を目指します。物販はサービスの利用を支えるとともに、収益源の一つとします。

| 構想商品 | 課金システムにおける役割 | 試作時の確認事項 |
| --- | --- | --- |
| 自宅用スマート薬箱 | 服用と期限内の記録を行う場所をまとめる | 収納、開閉、タグの読取位置 |
| NFC内蔵ポーチ | 外出先でも記録できるようにする | 携帯性、素材と読み取りの相性 |
| 追加タグ・アクセサリー | 複数の置き場所で記録しやすくする | 登録、交換、紛失時の対応 |

現在のNFC対応はAndroidで、iOSはQRです。iOS向け商品ではQRの貼付・表示方法も検討します。

画像は商品構想のイメージです。USB-C充電、約2週間の使用期間、収納寸法、フタを閉じた状態での読み取りは未検証・未確定です。掲載画面も現在の実装画面を保証しません。電子回路・充電機能・開閉検知・服用の自動検知は本リポジトリに実装していません。

## 収益設計と費用

実課金は服薬を後押しするためのプロダクトの中核です。一方、課金された金額を誰が受け取るか、運営側がどの割合を収益にするかは未確定です。利用者からの課金総額を、そのまま事業者の売上として扱う計画はまだ決めていません。

今後は、課金額の帰属・配分、サービス利用料の有無、薬箱・ポーチの物販利益を組み合わせて事業性を検討します。利用者の飲み忘れが減るほどペナルティ課金も減るため、**飲み忘れが減った状態でもサービスを継続できる収益設計**を目指します。成功の中心指標は飲み忘れの減少とします。

採算には、決済手数料、サーバー運用、アプリ保守、問い合わせ・返金対応、集客費を含めます。物販には製造、検品、梱包、配送、在庫、返品対応の費用も加わります。現在のローカルデモの運用費を、そのまま本番サービスの費用として見積もることはできません。

## 展開の段階

| 段階 | 実施内容 | 確認すること |
| --- | --- | --- |
| 1. 課金体験の検証 | 疑似決済デモで予定登録から期限経過まで試す | 課金条件の理解、操作のしやすさ、利用意向 |
| 2. 本番課金基盤の構築 | サーバー判定、決済連携、同期、取消処理を整備 | 二重課金防止、通信障害・記録遅延への対応 |
| 3. 限定的な実課金検証 | 条件に同意した参加者に実課金で提供 | 飲み忘れの変化、利用負担、誤判定、継続率 |
| 4. サービス・物販の展開 | 検証結果を反映し薬箱・ポーチとともに提供 | 利用継続、サポート体制、採算 |

薬局や生活雑貨店などの販路は候補として検討します。提携済みの事実を示すものではありません。

## 検証指標

- 飲み忘れの変化：利用前後や通知のみの条件と比較し、参加者の申告と記録の両面から確認。
- 期限内記録率：対象となる服用予定のうち期限内に記録された割合。
- 行動と記録の一致：課金回避のために記録だけを行っていないかを聞き取りで確認。
- 利用継続と負担：1週間・4週間時点の継続率、課金による負担、休止・解約理由。
- 課金の信頼性：誤判定、二重課金、決済失敗、取消・返金、問い合わせの件数。
- 事業の持続性：飲み忘れが減った場合の収支、利用者あたりの運用費、物販利益。

これらは今後の測定項目です。現在のデモに外部分析送信は実装していません。記録率を実際の服用率や治療効果と同一視せず、実課金が飲み忘れ防止につながっているかを検証します。
